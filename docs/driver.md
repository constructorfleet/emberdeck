# GRBL driver package

`driver.Validate(program)` checks the full program and returns its executable line count. `driver.Stream(ctx, conn, program, onProgress)` streams without interactive controls. `driver.StreamControlled(ctx, conn, program, commands, onProgress, onState)` also accepts `driver.Pause` and `driver.Resume` through a command channel. Both APIs send one source line at a time, wait for its acknowledgement, report acknowledged line counts, and send and acknowledge an injected `M5` cleanup command before waiting for `<Idle...>`. Progress counts uploaded executable lines; cleanup is excluded. After its program and context validate, the stream owns and closes the connection when it returns, including successful completion, so the read pump can always be joined. Invalid arguments return before ownership transfers.

`onState` receives exact GRBL state fields from status reports matched to a current status query (for example `Idle`, `Run`, `Hold:1`, or `Hold:0`); stale reports from a query already in flight when a control arrives are not reported as confirmation. An optional final `onApplied` callback reports when `!` or `~` has actually been written. This is an application receipt, not controller confirmation: workers must wait for a later fresh status before reporting paused or resumed. Stale and unsolicited statuses cannot satisfy that confirmation. A queued Pause gates source lines even during an outstanding acknowledgement. The driver sends `!`, allows one status query at a time at no more than 5 Hz, and remains gated through `Hold:1`; it treats a fresh `Hold:0` or `Idle` after the pause request as confirmation. Resume sends `~` only after a confirmed hold and keeps source output gated until a fresh `Run` or `Idle` report. An externally observed Hold also gates output and is never resumed automatically. No source line or injected `M5` is sent during a hold. A valid paused status can continue indefinitely; missing status reports time out after 30 seconds, and a hold or resume transition must complete within 30 seconds.

The program is validated in full before any bytes are sent. Input must be ASCII; GRBL realtime characters (`!`, `?`, `~`, Ctrl-X) in executable text are rejected. Semicolon and parenthetical comments are stripped safely; nested or unterminated parenthetical comments are rejected. Lines are trimmed, blank lines are skipped, CRLF is accepted, and executable lines may contain at most 79 bytes, matching GRBL's 80-byte line buffer including its terminator.

A controller error or unexpected response returns an error. Missing acknowledgements time out after 30 seconds. The initial status handshake ignores a GRBL welcome banner if the serial device emits one, but fails closed on busy, alarm, or other non-Idle states. On cancellation or a streaming error after controller interaction, the driver makes a bounded best-effort feed-hold and soft-reset write, then closes the connection to interrupt pending I/O. This is a software request only; it is not an emergency stop and does not guarantee that motion has stopped. Keep physical emergency stops and enclosure interlocks independent.

The wire boundary is `io.ReadWriteCloser`, so a serial adapter and simulator can provide the same interface. `driver.NewSimulator()` returns an in-memory endpoint that acknowledges commands and reports `Hold:1` followed by `Hold:0`; it supports resume and reset for development and tests. It does not model physical motion. The package does not open a serial port or manage job persistence. Tests exercise the public wire protocol with both `net.Pipe` and the simulator.

Protocol basis: [gnea/grbl interface documentation](https://github.com/gnea/grbl/blob/master/doc/markdown/interface.md) and [realtime commands](https://github.com/gnea/grbl/blob/master/doc/markdown/commands.md).

## Worker package

`worker.Run(ctx, serverURL, key, driverID, connector)` owns a unique session, polls for assignments, streams one assigned lease through the connector, and reports progress and terminal state. Poll failures fail closed and cancel an active stream. Terminal report retries reuse the same job ID and lease, so a lost HTTP response cannot cause the job to be resent to the controller. The worker package does not start physical drivers by itself; callers provide a connector for the intended wire endpoint.
